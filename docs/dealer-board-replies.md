# Dealer Network Board replies and topic reopening

- Read status only changes the notification; topics remain in the Board. Active includes closed but unarchived topics. The Archived filter has its own search. Open topic and notifications choose the topic's current tab and retain the UUID in the URL. A copied link can return to the same topic after the fixed Dealer Portal sign-in route; access still depends on the existing recipient list.
- The existing active/open discussion accepts five top-level branches, with 200 characters and up to three optional photos on each comment. A top-level comment accepts five direct replies of 150 characters and one optional photo each. There is no reply to a reply. Removed comments remain as placeholders only while their surviving replies need a parent. Removing the last reply frees an empty removed branch's slot. Former content over the limits stays readable; it is not truncated or deleted.
- Members can edit only their own visible comment or reply while the discussion is active/open. Text edits preserve already attached photos. New or replacement photos are not offered during text editing. Deleting a comment or reply hides its photos and leaves unrelated responses intact. Private Message opens the existing Dealer Portal conversation flow; it does not send anything automatically.
- Admin's Update Topic edits the title and already-existing announcement/discussion text on draft and active topics. It does not create another post, change the recipient list, resend notifications, change the poll, or change topic lifecycle. Closed and archived content remains read-only for members; IDS can still moderate an individual response. Moderation notes stay private to Admin.
- Images use the private Board bucket and separate upload tickets scoped to the authenticated author, discussion, and exact reply parent. The server verifies actual size, signature and decoded image and writes normalized JPEGs. The database binds only verified, unexpired tickets; photo reads recheck the current recipient or Admin relationship and do not cache responses. Original filenames, raw object paths, moderation reasons and full member display names are not returned in the member Board DTO.

## Release ordering if separately approved

1. Apply only the reviewed additive Board migration on an isolated staging DB first. It creates two service-role-only RLS tables, the private `dealer-network-board-private` bucket, and replaces/extends Board functions with compatible positional/named legacy call arguments. It does not change historical rows. Deploy the app only after the migration is present.
2. Verify real signed resumable Storage/TUS in that staging environment: authorize and post three regular photos and one direct-reply photo with synthetic members; reject false file types, replay/cross-parent IDs, and unauthorized reads; verify current members and Admin can read an attached normalized JPEG without caching; verify unlink-on-removal visibility and retention of surviving replies. Use synthetic users and a separate Storage bucket. A local SQL/React/Sharp test is not a hosted Storage round-trip.
3. Roll back the application if necessary without dropping the new tables or deleting uploaded rows. Old application builds still call the database's older argument pattern. The database continues enforcing the new limits, so the old UI may display less specific validation guidance during rollback.
